1. Introduction

A language model learns the statistical patterns of a language by training on large amounts of text. Its job is simple: given a sequence of words, predict what word is most likely to come next. This is one of the oldest and most well-studied problems in natural language processing (NLP), and it is the foundation for modern tools like autocomplete, machine translation, and large language models like ChatGPT.

In this project, I trained and compared four different neural network architectures on a collection of 18 classic English books from Project Gutenberg:

  • A Dense Neural Network — no memory of word order
  • An LSTM (Long Short-Term Memory)
  • A GRU (Gated Recurrent Unit)
  • A Bidirectional LSTM

The main evaluation metric is perplexity — lower is better. I also compared all models against two baselines (random and unigram) to give the results proper context.

Key result: The GRU achieved the best validation perplexity of 503.9 — 19.8× better than random guessing and 1.69× better than a frequency-only unigram model.

3. Preprocessing

Three steps were applied to the raw text before any model training:

Step 1 — Lowercase Normalization

All tokens converted to lowercase so The and the map to the same vocabulary entry. Without this, the same word would appear multiple times in the vocabulary with different capitalizations, wasting capacity.

Step 2 — Remove Non-Alphabetic Tokens

Only tokens passing word.isalpha() were kept. Punctuation marks, numbers, brackets, and dashes were removed. This eliminated 486,213 tokens (18.5%) of the raw corpus, leaving 2,135,400 clean tokens.

Step 3 — Vocabulary Cutoff at 10,000 Words

The corpus has over 51,000 unique words but most appear only once or twice. I kept the 10,000 most frequent words and replaced everything else with the special token <UNK>. These 10,000 words cover 96.21% of all tokens — the vocabulary coverage curve confirms that going beyond 10,000 gives very little extra coverage.

Figure 3 — Vocabulary Coverage Curve (Part 2) Cumulative corpus coverage as vocabulary size increases from 1 to 51,156. Diminishing returns visible beyond 10,000 words.

Sequence Construction

A sliding window was used to create input-output pairs from the cleaned token sequence:

  • Context window length: 20 words
  • Stride: 3 (window advances 3 positions each step)
  • Total sequences: 711,794
  • Each input is 20 word IDs; the target is the 21st word

4. Model Architectures

All four models solve the same problem: given 20 word IDs as input, predict which of the 10,000 vocabulary words comes next. This is a 10,000-class classification problem.

Every model shares three components:

  • Embedding layer (10,000 × 64): Maps each word ID to a 64-dimensional learnable vector
  • Dropout (rate = 0.3): Randomly zeros 30% of activations during training to prevent overfitting
  • Output Dense layer (10,000 units, softmax): Outputs a probability distribution over the vocabulary

Model 1 — Dense Neural Network 2,290,832 parameters

Input(20) → Embedding(10000,64) → Flatten(1280)
          → Dense(256, ReLU) → Dropout(0.3)
          → Dense(128, ReLU) → Dropout(0.3)
          → Dense(10000, softmax)

Flattens the 20×64 embedding into a single 1,280-dimensional vector before passing it through two fully connected layers. This model has no concept of word order — it treats all 20 context words as a flat set of features.

Model 2 — LSTM 2,028,816 parameters

Input(20) → Embedding(10000,64) → LSTM(128)
          → Dropout(0.3) → Dense(10000, softmax)

Reads the word sequence one step at a time. Three internal gates (forget, input, output) control what information is kept and what is discarded at each step. This allows it to capture dependencies between words far apart in the sequence.

Model 3 — GRU ⭐ Best Model 2,004,496 parameters

Input(20) → Embedding(10000,64) → GRU(128)
          → Dropout(0.3) → Dense(10000, softmax)

A simplified LSTM that uses only two gates (reset and update) and merges the cell and hidden state into one vector. Has roughly 25% fewer recurrent parameters than the LSTM. Trains faster and achieves better perplexity in this experiment.

Model 4 — Bidirectional LSTM 1,996,048 parameters

Input(20) → Embedding(10000,64) → Bidirectional(LSTM(64))
          → Dropout(0.3) → Dense(10000, softmax)

Two LSTM layers run simultaneously — one reads left to right, one reads right to left — and their outputs are concatenated into a 128-dimensional vector (64 per direction). Despite the more complex architecture, it actually has the fewest parameters because each direction only needs 64 units.

6. Results & Evaluation

What is Perplexity?

Perplexity is the standard evaluation metric for language models:

Perplexity = exp(cross-entropy loss)

A perplexity of N means the model is, on average, as uncertain as if it had to uniformly choose from N options at each step. Lower is better.

  • A model guessing uniformly over 10,000 words: perplexity = 10,000
  • A unigram model using word frequencies but no context: perplexity = 852.6
  • A good learned model: perplexity << 852

Why is test perplexity (751) higher than validation (504)?
This is expected and not a bug. The split is chronological, so the test set is the very last portion of the corpus — the text furthest from the training distribution in time and topic. Early stopping was tuned on validation loss, so the model is optimized for the validation segment. Some generalization gap to a different chronological segment is inherent to this evaluation design.

8. Analysis & Discussion

Why did the GRU win?

The GRU achieved the best validation perplexity (503.9) with fewer parameters than the LSTM and faster training. Looking at the perplexity learning curves (Part 4), the GRU drops quickly and levels off around epoch 3–4, while the LSTM needs more epochs to converge and the Dense NN's validation loss actually starts going up after epoch 2.

The GRU's advantage over the LSTM is consistent with findings in the literature: for short-to-medium sequences (our context is 20 words), the simplified gating of the GRU is sufficient to capture the important dependencies without the extra parameters of the LSTM's separate cell state.

Why did the Dense NN perform worst?

The Dense NN has the most parameters (2.29M) but the worst perplexity (592.5). When the 20 word embeddings are flattened into a single vector, all positional information is lost — "the dog bit the man" and "the man bit the dog" look identical as inputs. Language is inherently sequential, and a model with no positional awareness cannot capture this.

Why did the Bidirectional LSTM underperform the GRU?

The BiLSTM was expected to benefit from seeing both past and future context. But language modeling is a fundamentally left-to-right task — we want to predict the next word using only past words. During training, the backward LSTM reads future words to help encode each position, which can add noise rather than signal for this specific objective. More complex is not always better. The BiLSTM would likely outperform the GRU on tasks like text classification or named entity recognition, where full-sentence context helps.

Honest assessment of the results

GRU is 1.69× better than the unigram baseline (852.6 → 503.9). Most of the predictability in literary text comes from word frequency patterns, not from sequential context. This is a known and expected finding at this model scale. Modern large language models (GPT-4, Claude) show much larger improvements because they use billions of training tokens, much deeper networks, and longer context windows.

What did the model actually learn?

The word embedding PCA visualization (Part 6) shows that the GRU learned meaningful semantic structure just from predicting words:

  • "Captain" sits isolated from the main cluster — it appears almost exclusively in Moby Dick contexts
  • "Holy" and "god" are pulled in different directions even though both are religious — they appear in different grammatical positions (adjective vs noun)
  • Maritime words (whale, sea, sailor) form a loose cluster
  • Conflict words (war, battle, sword, fight) cluster separately from emotion words

This is direct evidence the model learned word meaning, not just word frequency.

The top-K prediction charts confirm context-sensitivity: after a Moby Dick seed phrase, maritime words get higher probability; after a biblical seed phrase, religious vocabulary rises. The model is not just counting words — it is doing sequential reasoning.

Overfitting

The train vs. validation perplexity curves show a large gap: training perplexity drops to around 100–150 while validation stays around 500. Models are memorizing training sequences better than they generalize. This is common with a small corpus (only 18 books). Dropout and early stopping reduced this gap but did not eliminate it. A larger or more diverse dataset would help.

The temperature=0.5 collapse is a known artifact of word-level models with an explicit <UNK> token. Character-level or subword (BPE) tokenization would eliminate this problem.

9. Conclusion

The GRU is the best architecture for word-level language modeling on the Project Gutenberg corpus. It achieves perplexity 503.9 on validation — 19.8× better than random and 1.69× better than a frequency-only unigram model — with the second-fewest parameters and the fastest convergence of the four models tested.

The main findings are:

  • Sequential inductive bias matters. The Dense NN (no memory of order) performs worst despite the most parameters.
  • GRU > LSTM > BiLSTM > Dense NN for this task and dataset size.
  • Bidirectional context does not help for next-word prediction — language modeling is a left-to-right task.
  • Honest result: the 1.69× improvement over unigram shows that word frequency is the dominant signal at this scale. Context helps, but not dramatically.
  • The model learned semantics — the embedding PCA shows clear thematic clustering across maritime, religious, and conflict vocabulary.

Future Directions

  • Stacked LSTM/GRU layers for more representational capacity
  • Pre-trained word embeddings (GloVe, Word2Vec) to start with better word representations
  • Subword tokenization (BPE) to eliminate the <UNK> token problem
  • Attention mechanisms and transformer-based architectures (GPT-style)
  • Larger and more diverse training corpus (e.g., all of Wikipedia)
